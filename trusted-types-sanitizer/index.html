Why Streaming Broke createHTML

// Chunk 1: "<scr" Chunk 2: "ipt>evil()</script>" await response.body.pipeTo(el.streamHTMLUnsafe());
  • createHTML(chunk): Per-chunk sanitization is unsafe; buffering breaks streaming & parses twice
  • createParserOptions(opts): Configures the stateful HTML parser directly

In w3c/trusted-types#594 we tried to fit streaming HTML into Trusted Types. Sanitize-per-chunk is insecure unless the policy buffers and re-implements an HTML tokenizer/parser in JS. Meanwhile, the browser now has a native Sanitizer API that sanitizes while parsing.

The Insight: Bless the Parser Options

“If you can trust all parser options including sanitizer, you don't have to trust the input.”

— Anne van Kesteren (w3c/trusted-types#594)

  • policy.createParserOptions(options) → TrustedHTMLParserOptions
  • Controls sanitizer and runScripts in the HTML parser

Instead of transforming untrusted strings in JS, a Trusted Types policy can return a TrustedHTMLParserOptions token that configures the browser's built-in HTML parser sanitizer and script execution mode.

What Sinks Does It Cover?

  • Unsafe HTML sinks: setHTMLUnsafe(), parseHTMLUnsafe()
  • Streaming incubation (html#2142): streamHTMLUnsafe()
  • Legacy sinks: innerHTML, outerHTML, insertAdjacentHTML(), createContextualFragment()
  • Safe sinks (setHTML, parseHTML, streamHTML): Bypass Trusted Types

All fragment parsing sinks and parseHTMLUnsafe now route through "get trusted type compliant input", which checks for TrustedHTMLParserOptions or defaultPolicy.createParserOptions before falling back to createHTML.

Scenario 1: Default Policy

// CSP: require-trusted-types-for 'script' trustedTypes.createPolicy("default", { createParserOptions(options, type, sink) { return { sanitizer: "default", runScripts: false }; } }); el.innerHTML = untrustedString; range.createContextualFragment(untrustedString);

By defining createParserOptions on the default policy, existing apps using innerHTML, insertAdjacentHTML, or createContextualFragment automatically get native single-pass sanitization during parsing, and can block createContextualFragment's implicit runScripts: true.

Scenario 2: Streaming & Custom Options

const policy = trustedTypes.createPolicy("stream", { createParserOptions({ sanitizer = new Sanitizer({}) }) { sanitizer.removeUnsafe(); // sanitizer is already a Sanitizer instance return { sanitizer, runScripts: false }; } }); const opts = policy.createParserOptions({ sanitizer: { removeElements: ["img"] } }); el.setHTMLUnsafe(untrustedHTML, opts); await response.body.pipeTo(el.streamHTMLUnsafe(opts));

The UA normalizes options.sanitizer into a fresh Sanitizer instance before invoking createParserOptions, so policies can mutate sanitizer directly. For streaming sinks where no string exists up front, createHTML cannot be used (throwIfMissing = true).

Precedence & Fallbacks

  • TrustedHTMLParserOptions: Satisfies Trusted Types
  • defaultPolicy.createParserOptions: Takes precedence over createHTML
  • Fallback to createHTML: Non-streaming only (streaming throws TypeError)
  • TrustedHTML + author sanitizer / runScripts: true: Uses defaultPolicy.createParserOptions, or throws TypeError if absent (#615)

When no TrustedHTMLParserOptions is provided and defaultPolicy.createParserOptions is missing, non-streaming sinks fall back to createHTML / TrustedHTML for backwards compatibility, whereas streaming sinks (streamHTMLUnsafe) throw a TypeError. If TrustedHTML is passed together with unvetted author options ({ runScripts: true } or a custom sanitizer), it routes through defaultPolicy.createParserOptions if defined, or throws a TypeError if absent.

Future Sinks (html#13013)

  • iframe.srcdoc (html#12756)
  • document.write() / writeln()
  • DOMParser.parseFromString(str, "text/html") & execCommand("insertHTML")
  • XML innerHTML & XML DOMParser: Fall back to createHTML

Tracked in whatwg/html#13013: once sanitize-while-parsing (whatwg/html#12756) lands for the full document parser, legacy full-document HTML sinks like iframe.srcdoc, document.write(), and DOMParser("text/html") can also route through defaultPolicy.createParserOptions.

Outlook
