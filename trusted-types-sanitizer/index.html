Sanitizer in Trusted Types

createParserOptions: Trusting the parser configuration, not just the string

Noam Rosenthal & Frederic Braun

TPAC 2026
Dublin, Ireland & online
26–30 October 2026

Spec PRs: w3c/trusted-types#606 and whatwg/html#12583. Issues: w3c/trusted-types#594 and whatwg/html#13013.

Why Streaming Broke createHTML

  • createHTML(str): Needs full string up front; forces a double parse
  • createParserOptions(opts): Configures the stateful HTML parser directly

In w3c/trusted-types#594 we tried to fit streaming HTML into Trusted Types. Sanitize-per-chunk is insecure unless the policy buffers and re-implements an HTML tokenizer/parser in JS. Meanwhile, the browser now has a native Sanitizer API that sanitizes while parsing.

The Insight: Bless the Parser Options

“If you can trust all parser options including sanitizer, you don't have to trust the input.”

— Anne van Kesteren (w3c/trusted-types#594)

  • New policy callback: createParserOptions(options)
  • Returns an opaque, immutable TrustedHTMLParserOptions
  • Controls sanitizer and runScripts directly in the native HTML parser

Instead of transforming untrusted strings in JS, a Trusted Types policy can return a TrustedHTMLParserOptions token that configures the browser's built-in HTML parser sanitizer and script execution mode.

What Sinks Does It Cover?

  • Modern Unsafe Sinks: setHTMLUnsafe(), parseHTMLUnsafe(), streamHTMLUnsafe()
  • Legacy Fragment Sinks: innerHTML, outerHTML, insertAdjacentHTML(), createContextualFragment()
  • Safe Sinks (setHTML, parseHTML, streamHTML): Already safe by default — bypass Trusted Types entirely

All fragment parsing sinks and parseHTMLUnsafe now route through "get trusted type compliant input", which checks for TrustedHTMLParserOptions or defaultPolicy.createParserOptions before falling back to createHTML.

Scenario 1: Default Policy

trustedTypes.createPolicy("default", { createParserOptions(options) { return { sanitizer: "default", runScripts: false }; } }); // Sanitizes while parsing — no DOMPurify needed! el.innerHTML = untrustedString; range.createContextualFragment(untrustedString);

By defining createParserOptions on the default policy, existing apps using innerHTML, insertAdjacentHTML, or createContextualFragment automatically get native single-pass sanitization during parsing, and can block createContextualFragment's implicit runScripts: true.

Scenario 2: Streaming HTML

const policy = trustedTypes.createPolicy("stream", { createParserOptions({ sanitizer }) { const s = new Sanitizer(sanitizer); s.removeUnsafe(); return { sanitizer: s, runScripts: false }; } }); const opts = policy.createParserOptions({ sanitizer: cfg }); await response.body.pipeTo(el.streamHTMLUnsafe(opts));

For streaming sinks where no string exists up front, createHTML cannot be used (throwIfMissing = true). Either the caller passes a TrustedHTMLParserOptions from a named policy, or the default policy's createParserOptions supplies one.

Scenario 3: Precedence & Fallback Rules

  • Explicit TrustedHTMLParserOptions: Satisfies TT — raw strings allowed
  • Default policy has createParserOptions: Takes precedence over createHTML
  • No createParserOptions: Falls back to TrustedHTML / createHTML only when not streaming (streaming throws TypeError)
  • TrustedHTML + unvetted author options: Throws TypeError (prevents insecure blends, #615)

When no TrustedHTMLParserOptions is provided and defaultPolicy.createParserOptions is missing, non-streaming sinks fall back to createHTML / TrustedHTML for backwards compatibility, whereas streaming sinks (streamHTMLUnsafe) throw a TypeError because there is no full string to pass to createHTML. Also, passing a TrustedHTML together with unvetted author options ({ runScripts: true } or a custom sanitizer) throws a TypeError.

What's Not Covered Yet (Future: html#13013)

  • iframe.srcdoc — Straightforward with sanitize-while-parsing (html#12756)
  • document.write() / writeln() — Multiple calls share one active parser, but doable via default policy
  • DOMParser.parseFromString() & execCommand("insertHTML")
  • XML documents (innerHTML): Sanitizer is HTML-parser-only → falls back to createHTML

Tracked in whatwg/html#13013: once sanitize-while-parsing (whatwg/html#12756) lands for the full document parser, legacy full-document sinks like iframe.srcdoc, document.write(), and DOMParser can also route through defaultPolicy.createParserOptions.
