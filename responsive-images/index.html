Blurry Images vs. Wasted Bandwidth

Wasted Bandwidth

  • 3x bitmaps on tiny thumbnails
  • 10× over-fetch on object-fit: contain

Blurry Images

  • 33–78% under-fetch on object-fit: cover
  • scale-down & none upscale small images
  • Soft zoomable heroes

Every responsive image trades off sharpness against bandwidth. Today users regularly get the worst of both worlds: wasted megabytes on secondary thumbnails and letterboxed banners, and blurry images on square object-fit: cover cards, upscaled scale-down icons, and zoomable hero photos.

Who Should Hold the Knobs?

  • Browsers are built for interoperability
  • Websites know the business trade-offs (hero vs. 40th thumbnail)
  • Goal: Standardize the browser baseline; give the tuning knobs to the website

In 2014 the spec left source selection "implementation-defined" so UAs could guess bandwidth heuristics. Over a decade we learned UAs are built for interop—they can't know if an image is a conversion-critical product photo or a secondary thumbnail. Moving the knobs to the website empowers the party that can actually A/B test business impact.

1. Standardize Selection (#13077)

  • All engines now use the same baseline: first candidate >= targetDensity
  • Chrome also avoids downloading a lower-res source when a higher-res one is already loaded
  • Proposal: Spec both normatively

Since late 2024, WebKit, Gecko, and Blink all use the same density threshold, and Chrome's optimization to reuse an already-loaded higher-res image can be standardized rather than left implementation-defined. This unlocks WPT tests and deterministic knobs.

2. Target Density Knob (#13069)

<!-- Save ~44% pixels below the fold --> <img srcset="..." sizes="auto" densityscale="0.75"> <!-- Extra sharpness for zoomable hero --> <img srcset="..." sizes="auto" densityscale="1.5">
  • No more lying in sizes or lying in w descriptors (img?w=720 800w)

Because lying in sizes breaks sizes="auto", production sites like Airbnb literally lie in their w descriptors (writing 800w for a 720px file), which breaks CDN cache sharing and 2D aspect ratios. A densityscale (or resolutionpriority) knob gives sites direct control.

3. 2D sizes & object-fit (#12248)

<img loading="lazy" sizes="auto" style="width: 400px; height: 400px; object-fit: cover" srcset="sm.jpg 400w 300h, md.jpg 800w 600h">
  • cover: max(W, H·r) → fixes blurry cards
  • contain: min(W, H·r) → fixes 10× over-fetching
  • h descriptor: pre-fetch aspect ratio, zero infinite loops

PR #13053 revives the h descriptor in srcset as a pre-fetch aspect-ratio hint and makes sizes="auto" 2D and object-fit aware. Because the pre-fetch hint remains authoritative after load, it also fixes the spec's concrete-object-size infinite download loop.

4. Fix scale-down Upscaling (#11428)

<div style="width: 800px; height: 600px"> <img srcset="logo.png 200w" sizes="auto" loading="lazy" style="width: 100%; object-fit: scale-down"> </div>
  • Today: density = 200/800 = 0.25x → naturalWidth = 800px!
  • scale-down upscales the 200px logo to 800px blurry

Authors use object-fit: scale-down or none specifically so a small 200px image won't upscale to 800px. But because w descriptors derive naturalWidth from sizes (200 / 0.25 = 800px), scale-down upscales it to 800px anyway! We should not inflate naturalWidth past native 1x/DPR bounds for scale-down and none.

5. Expose True File Pixels (#12565)

// 800×600 file rendered in a 400px sizes="auto" box: img.naturalWidth; // 400 (just echoes layout width!) img.resourceWidth; // 800 (true file pixels) img.resourceHeight; // 600
  • Lets sites measure bandwidth waste in RUM & cap zoom UIs

With w descriptors (and PR #13046), naturalWidth always equals sourceSize—so under sizes="auto", naturalWidth just echoes clientWidth. Exposing resourceWidth and resourceHeight lets RUM telemetry measure over/under-fetching and lets lightboxes check real pixel headroom.

Summary

  • #13077: Normative selection + higher-res cache reuse
  • #13069: Density knob (densityscale)
  • #12248: 2D sizes + h descriptor for cover / contain
  • #11428: Don't upscale scale-down / none
  • #12565: True pixel dimensions (resourceWidth)
  • ▶ Live Demo: Blur & Bandwidth Visualizer

Together, these five issues standardize the browser baseline and give websites the knobs they need to eliminate both blurry images and wasted bandwidth.
