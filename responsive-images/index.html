Better Responsive Image Knobs

Moving sharpness vs. bandwidth control from the browser to the website

The User-Facing Problem

Every responsive image trades off sharpness against bandwidth.

Wasted Bandwidth

  • 3x bitmaps fetched for secondary thumbnail grids
  • 10× over-fetch on letterboxed object-fit: contain
  • Slower LCP & excess data usage

Blurry Images

  • 33–78% under-fetch on cropped object-fit: cover cards
  • object-fit: scale-down / none unexpectedly upscales small images
  • No way to request extra density for zoomable heroes

Users and site owners constantly hit two failure modes: either pages waste megabytes downloading excessive resolution for secondary thumbnails and letterboxed banners, or users see blurry images on square object-fit: cover cards, upscaled scale-down images, and zoomable product photos.

Evolving the 2014 Model

  • 2014 spec left selection "implementation-defined" so UAs could experiment with heuristics
  • UAs are designed for interop; websites know the business trade-offs
  • A browser can't tell a conversion-critical hero photo from the 40th feed thumbnail
  • Meanwhile, useful UA optimizations (like keeping an already-loaded higher-res image) can be standardized!

In 2014, leaving selection implementation-defined made sense for experimentation. Over time we learned that UAs are best at interoperable baseline behavior and cache/loaded-image reuse, while websites are the ones positioned to measure context-specific quality vs. bandwidth trade-offs.

The Theme: Standard Baseline, Website Knobs

Browser: Interop

  • Normative selection + loaded higher-res reuse (#13077)
  • Loop-free 2D & scale-down sizing (#12248, #11428)

Website: Control

  • Density multiplier knob (#13069)
  • 2D object-fit & h descriptors (#12248)
  • True pixel inspection (#12565)

Our goal is to standardize the browser's selection baseline and move the content-specific knobs to the website—giving site owners clean declarative tools to optimize and measure sharpness vs. bandwidth.

1. Normative Source Selection (#13077)

  • All three engines now share the same baseline density rule:
    • Sort ascending by density → pick first candidate >= targetDensity
  • Chrome also avoids fetching a lower-res source when a higher-res candidate is already loaded
  • Proposal: Standardize both the baseline rule and higher-res reuse normatively

Now that Chrome retired geometric-mean density rounding in late 2024, all engines use the same density threshold, and Chrome's optimization to keep an already-loaded higher-res image can be standardized rather than left implementation-defined. This unlocks WPT testing and predictable behavior.

2. Target Density Knob (#13069)

<!-- Save ~44% pixels on below-the-fold thumbnails -->
<img srcset="t-400.jpg 400w, t-800.jpg 800w"
     sizes="auto" densityscale="0.75" loading="lazy">

<!-- Extra headroom for a zoomable product hero -->
<img srcset="p-600.jpg 600w, p-900.jpg 900w"
     sizes="auto" densityscale="1.5" loading="lazy">
  • Stops sites from lying in sizes (breaks sizes="auto") or lying in w descriptors (img?w=720 800w)
  • Lets sites A/B test density per component to optimize LCP vs. conversion

Today, because lying in sizes doesn't work with sizes="auto", production sites like Airbnb literally lie in their w descriptors (writing 800w for a 720px file), which breaks CDN caching and 2D aspect ratios. A dedicated densityscale attribute (or resolutionpriority / CSS property) gives sites direct, honest control.

3. 2D sizes & object-fit (#12248 / #13053)

<img loading="lazy" sizes="auto"
     style="width: 400px; height: 400px; object-fit: cover"
     srcset="sm.jpg 400w 300h, md.jpg 800w 600h, lg.jpg 1200w 900h">
  • Fixes blurry cover cards: uses max(W, H·r) instead of 1D width
  • Fixes bloated contain banners: uses min(W, H·r) (up to 10× savings)
  • Fixes spec bug: pre-fetch w/h aspect ratio prevents infinite download loops

A 4:3 photo in a 400x400 object-fit: cover card is drawn at 533px wide, so 1D sizes under-fetches by 33%. Conversely, a portrait image in a wide object-fit: contain box over-fetches by up to 10x. Reviving the h descriptor in srcset gives the pre-fetch aspect ratio and eliminates the concrete-object-size oscillation loop.

4. Blurry Upscaling with scale-down & none (#11428)

<div style="width: 800px; height: 600px">
  <img srcset="logo-200.png 200w" sizes="auto" loading="lazy"
       style="width: 100%; height: 100%; object-fit: scale-down">
</div>
  • Authors use scale-down / none so small images don't upscale and blur
  • But sizes="800px" sets density = 200/800 = 0.25x → naturalWidth = 800px!
  • Result: scale-down and none upscale the 200px image to 800px

In #11428, when an author puts a 200w image inside an 800px container with object-fit: scale-down or none, they specifically want it not to upscale past 200px. Because w descriptors derive naturalWidth from sizes (200 / 0.25 = 800px), scale-down and none upscale the 200px image to 800px anyway! We need to avoid inflating naturalWidth past native 1x/DPR bounds for scale-down and none.

5. True Pixel Dimensions for RUM & Zoom (#12565)

// 800×600 file (800w) rendered in a 400px box with sizes="auto":
img.naturalWidth;   // 400 (always equals sourceSize / clientWidth!)
img.resourceWidth;  // 800 (true pixel width of the loaded file)
img.resourceHeight; // 600 (true pixel height of the loaded file)
  • With w descriptors (and PR #13046), naturalWidth always equals sourceSize
  • Exposing resourceWidth / resourceHeight lets sites measure pixel waste in RUM & cap zoom UIs

You can't optimize what you can't measure. With w descriptors (and especially PR #13046), naturalWidth is always equal to the resolved sizes width—so under sizes="auto", naturalWidth just echoes clientWidth. Exposing resourceWidth and resourceHeight (or currentPixelDensity) lets RUM scripts measure over/under-fetching and lets lightboxes check real pixel headroom without creating an offscreen new Image().

Summary: Putting Websites in Control

Issue Website Control / Interop Fix
#13077 Normative >= targetDensity baseline + higher-res cache reuse
#13069 Per-image density knob (densityscale / resolutionpriority)
#12248 2D sizes + h descriptor for object-fit: cover & contain (PR #13053)
#11428 Stop w descriptors from upscaling object-fit: scale-down & none
#12565 Expose true file pixel dimensions (resourceWidth / resourceHeight)

Together, these five issues standardize the browser's baseline behavior and give websites honest, declarative knobs to avoid both wasted bandwidth and blurry images.
