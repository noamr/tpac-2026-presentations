Parser-Aware MutationObserver

Bridging the HTML parser and the DOM

TPAC 2026
Dublin, Ireland & online

Explainer: https://github.com/WICG/declarative-partial-updates/blob/main/parser-mutation-records-explainer.md. Proposes extending MutationObserver with { parser: true } and Node/ShadowRoot with isParsing.

What the Parser Knows (and the DOM Forgets)

  • Is this element finished parsing? (open vs. closed tag)
  • Did a <template> just run? (shadowrootmode, for)
  • Which container triggered this parse? (innerHTML, setHTML, patch)

The HTML parser tracks the stack of open elements, consumes special <template> directives (Declarative Shadow DOM and <template for>), and knows the fragment context root—none of which is visible to MutationObserver today.

Why It Hurts Today

  • addedNodes fires on the start tag — children may not exist yet
  • Declarative Shadow Roots attach silently
  • Streaming <template for> patches are invisible to observers

Custom elements and hydration libraries cannot tell if an element's children have finished parsing (whatwg/dom#898, w3c/webcomponents#809); nextSibling hacks add 100ms+ latency and fail on last children. And DSD / streaming patches emit zero lifecycle records.

Proposal: { parser: true }

observer.observe(document, {
  childList: true,
  subtree: true,
  parser: true
});
  • node.isParsing & record.parsedElements
  • record.templateStatus & record.templateAttributes
  • record.parserContextElement

Opt-in via parser: true on MutationObserverInit. Existing observers pay zero overhead.

Knowing When Elements Finish: parsedElements

// Chunk 1: "<my-card><h2>Title</h2>"
myCard.isParsing; // true

// Chunk 2: "<p>Body</p></my-card>"
// record.parsedElements -> [p, my-card]
myCard.isParsing; // false

parsedElements lists elements that popped off the parser's stack of open elements. Whenever possible, it is coalesced onto existing childList records so no extra MutationRecords are allocated.

Observing Consumed <template>s

for (const r of records) {
  if (r.templateStatus === "start") {
    // DSD attached or <template for> patch started!
    console.log(r.templateAttributes.getNamedItem("for"));
  }
}
  • templateStatus: "start" → "update" → "end" | "abort"

Tracks both <template shadowrootmode> and <template for>. templateAttributes is a read-only NamedNodeMap that preserves object identity across all chunks of a single template without retaining a detached DOM tree.

Alternatives Considered

  • New record type ("parsedElement") — 2× record allocations
  • DOM events (parseend) — MutationEvent storm
  • Separate PatchObserver — loses ordering with DOM mutations

Piggybacking on MutationObserver's existing microtask batching and coalescing onto childList records keeps memory and CPU overhead near zero.

Discussion

  • Add Custom Element parsedCallback() on top of isParsing?
  • Feedback on { parser: true } shape?

If we add parsedCallback() on Custom Elements, its semantics can be defined directly on top of isParsing, while MutationObserver handles general subtree observation.
