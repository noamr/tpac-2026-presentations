Silent Focus Loss

  • activeElement resets to document.body with zero events
  • Focus traps & keyboard navigation break

Per HTML's node-remove focus fixup rule, removing the focused element resets focus to the viewport without firing blur or focusout. Gecko and WebKit fire nothing; Blink has been stuck with a legacy synchronous blur because libraries have no alternative (whatwg/html#12842).

Workarounds Today

MutationObserver

Radix UI, focus-trap

  • Runs on every DOM edit
  • Breaks in Shadow DOM

setInterval Polling

Material UI, Tridactyl

  • Polls every 200ms
  • Wastes CPU & lags

When a simple signal is missing from the platform, libraries end up inventing bent-backwards workarounds: either observing every single childList mutation on document.body or polling document.activeElement on a 200ms timer just to notice that focus silently dropped to body.

Proposal: focusreset on Document

document.addEventListener("focusreset", () => { fallbackElement.focus(); });
  • Fires in the mutation observer microtask
  • Plain Event — no detached node reference

Fires at Document at the end of the mutation observer microtask (after MutationObserver callbacks and slotchange). Omitting relatedTarget avoids keeping detached DOM subtrees alive and preserves closed Shadow DOM encapsulation.

Auto-Cancellation

item.remove(); nextItem.focus();
  • Only fires for unhandled focus loss
  • Tracks nested <iframe> focus
  • moveBefore() preserves focus → no focusreset

If script explicitly moves focus before the microtask runs (via .focus(), showModal(), or autofocus), the pending focusreset is cancelled so fallback handlers don't override it. If both an iframe button and the iframe itself are removed, focusreset only fires on the parent Document.

Timing: Microtask vs. Rendering

  • display: none: Resets activeElement & fires blur after layout
  • node.remove(): Resets activeElement synchronously
  • Microtask: Matches activeElement & catches rAF / ResizeObserver removals

Step 17 of update-the-rendering is for style changes (display:none) and updates activeElement + fires blur together. On DOM removal, activeElement is already reset synchronously; firing focusreset in the MutationObserver microtask keeps it in sync with activeElement and handles removals during rAF/ResizeObserver.

Why Not…

  • Sync blur: Re-entrancy hazard
  • Async blur on ancestor: Ancestor was never focused
  • relatedTarget: Leaks detached & closed Shadow DOM

Synchronous events during DOM removal are unsafe. Firing blur on a parent that was never focused is semantically wrong and breaks if ancestors are reparented. Omitting relatedTarget avoids detached DOM leaks and preserves closed Shadow DOM encapsulation.
