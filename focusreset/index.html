Silent Focus Loss

Remove the focused element from the DOM:

  • Focus silently drops to document.body
  • Zero events fired (no blur, no focusout)
  • Users lose their place; modal focus traps break

Per HTML's node-remove focus fixup rule, removing the focused element resets focus to the viewport without firing blur or focusout. Gecko and WebKit fire nothing; Blink has been stuck with a legacy synchronous blur because libraries have no alternative (whatwg/html#12842).

Today's Hacks

MutationObserver

Radix UI, focus-trap

  • Runs on every DOM edit
  • Fails in Shadow DOM

setInterval Polling

Material UI, Tridactyl

  • Polls every 200ms
  • Wastes CPU & lags

Major UI libraries either observe every childList mutation on document.body or poll document.activeElement on a 200ms timer just to detect when focus fell back to body.

Proposal: focusreset on Document

document.addEventListener("focusreset", () => {
  fallbackElement.focus();
});
  • Fires in the mutation observer microtask (before paint)
  • Plain Event — no reference to the detached node

Fires at Document at the end of the mutation observer microtask (after MutationObserver callbacks and slotchange). Omitting relatedTarget avoids keeping detached DOM subtrees alive and preserves closed Shadow DOM encapsulation.

Smart Auto-Cancellation

item.remove();
nextItem.focus(); // -> Cancels pending focusreset!
  • Only fires for unhandled focus loss
  • Nested <iframe>s: checks hasFocus() on removal & dispatch
  • moveBefore() preserves focus → no focusreset

If script explicitly moves focus before the microtask runs (via .focus(), showModal(), or autofocus), the pending focusreset is cancelled so fallback handlers don't override it. If both an iframe button and the iframe itself are removed, focusreset only fires on the parent Document.

Why Not…

  • Sync blur on removal? Re-entrancy hazard mid-removal
  • Async blur on ancestor? Ancestor was never focused
  • Rendering-step timing? Too late if removed inside rAF

Synchronous events during DOM removal are unsafe. Firing blur on a parent that was never focused is semantically wrong and breaks if ancestors are reparented. Microtask timing catches removals before rendering.
